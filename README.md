### TP_hackathon_61

## О проекте
 TP_hackathon_61 — система автоматической обработки корпоративной почты, предназначенная для сортировки входящих обращений сотрудников по тематическим категориям.

Основная особенность проекта — устойчивость к появлению новых типов обращений. Если письмо невозможно автоматически классифицировать, система позволяет пользователю вручную определить категорию и автоматически обучается на этом решении для будущих запусков.

# Основные возможности

1. Автоматическая классификация писем

2. Проверка корректности данных перед запуском

3. Интерактивная обработка неизвестных обращений

4. Самообучающийся словарь категорий

5. Логирование действий 

6. Сбор статистики по загруженным письмам

7. Обработка ошибок и поврежденных файлов

8. Полноценное тестовое покрытие

## Этап 1. Предварительная валидация

Перед запуском основной обработки выполняется проверка.

Валидатор автоматически проверяет:
1. наличие папки с исходными письмами
2. наличие писем в папке для последующей обработки
3. наличие конфигурационных файлов

Если обнаружена критическая ошибка, запуск обработки блокируется до её исправления, а пользователю поступает сообщение об ошибке и ее типе.

Пример запуска:
- происходит автоматически во время запуска программы
- также в терминале можно написать python validate.py
- автоматически через: ./run.sh


## Этап 2. Автоматическая классификация

После успешной проверки система анализирует содержимое каждого письма.
Для каждой категории хранится набор ключевых слов.

Пример:

{
  "hr": 
  [
    "отпуск",
    "больничный",
    "сотрудник",
    "onboarding",
    "оформление",
    "увольнение",
    "вакансия",
    "собеседование",
    "hr",
    "кадровый"
  ]

  "meetings_events": 
  [
    "meeting",
    "встреча",
    "созвон",
    "conference",
    "zoom",
    "teams",
    "приглашение",
    "календарь",
    "демо",
    "презентация"
  ]

}

Категория выбирается по максимальному количеству найденных совпадений(если количество совпадений одинаковое, то письмо определяется в папку по очередности их расположения).


## Этап 3. Интерактивная обработка неизвестных писем

Одной из основных задач проекта является устойчивость к новым типам обращений.

Если письмо не соответствует ни одной существующей категории, система помещает его в папку “unknown” автоматически.

И запускается интерактивный режим.

# Пример:

Письмо: mail_01000.txt
Ot kogo: ав
Komu: ав
Data: 25.03.2025 17:46
Tema: абракадабра
ковер

Категория не определена.

Далее пользователю предоставляется выбор из всех существующих категорий, где он самостоятельно может определить категорию этого письма или отправить письмо в неопознанные(13)

Выберите категорию:

1. spam_phishing

2. newsletters_marketing

3. it_support

4. access_requests

5. monitoring_alerts

6. contracts_documents

7. drafts

8. finance

9. hr

10. meetings_events

11. external_requests

12. attachments_processing

13. unknown

Введите номер категории:
(нужно вводить именно номер категории, а не ее название)

После выбора письмо переносится в указанную пользователем папку.

# Самообучающийся словарь
После выбора категории система анализирует текст письма и сохраняет новые ключевые слова для выбранной категории.

Например:

Исходное письмо содержит слова:

"ковер, абракадабра..."

Пользователь относит письмо к категории:

<hr>

После подтверждения словарь автоматически обновляется:
{
    "hr": [
        "отпуск",
        "больничный",
        "сотрудник",
        "onboarding",
        "оформление",
        "увольнение",
        "вакансия",
        "собеседование",
        "hr",
        "кадровый"
        "абракадабра"
        "ковер"
        ...
    ]
}

# Накопление знаний между запусками

Обновленный словарь сохраняется, и при дальнейшей обработке и распределение файлов, добавленные слова будут учитываться и распределение других писем произойдет по аналогии и мнение пользователя спрашиваться не будет.
Таким образом классификатор постепенно адаптируется к реальным данным без изменения исходного кода.

Это позволяет:
1. уменьшать количество неопознанных писем
2. автоматически учитывать новые типы обращений
3. повышать точность классификации
В целом это уменьшает количество времени, которое пользователю понадобиться на ручной перебор и распределение неопознанных писем.


## Этап 4 формирование статистики

После завершения обработки формируется отчет:

Пример:

Удачные: 108
Провалившиеся: 5
access_requests: 10
attachments_processing: 11
errors: 5
external_requests: 3
finance: 4
hr: 7
it_support: 49
meetings_events: 3
monitoring_alerts: 7
newsletters_marketing: 5
spam_phishing: 4
unknown: 1

В отчете можно посмотреть статистику сколько писем попала в каждую категорию.
Отчет формируется сразу после первоначального распределения писем, а также после интерактивного режима(то есть пользователь может отслеживать статистику перемещения файлов).


## Работа с ошибками

Система предусматривает обработку следующих ситуаций:

- неподдерживаемой расширение файла
- нечитаемый файл
- пустые или файлы без ключевых слов(на усмотрение пользователя//переносятся в unknown)


Работа приложения не прерывается при обработке отдельных ошибочных файлов, а пользователю в итоговой статистке будет отмеченно, какие файлы не удалось распознать и почему.


## Логирование

Все действия записываются в журнал.
С помощью логера пользователю выводится дата и время, а также информация о внесение файла в определенную папку или сообщение об ошибке.


## Тестирование
Запуск тестов:
pytest

Покрывают:
- классификацию
- интерактивный режим с unknown письмами
- граничные случаи(проблемы с файлами)
- роутинг(создание папок и копирование файлов)
- всю работу программы(интеграционный тест)
- работу валидатора
